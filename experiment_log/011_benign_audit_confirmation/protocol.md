# One benign-audit supervision revision

This is a fresh confirmation study motivated by 010's unsuccessful overall
intervention. It is not an untouched test of that original protocol. The question
remains whether corrective training of task-prepared WideSeek improves selective
cooperation and transfers to improper omission without impairing legitimate work.

The saved 010 token IDs/labels were reconstructed through the original tokenizer,
encoder and collator and matched to all four GPU training metadata hashes. The
400 task-specific benign examples in its corrective arm masked empty-audit and
stopping targets; the 400 falsification examples supervised incident reports and
stopping. Neutral serialization separately supervised 100 empty and 100 nonempty
answers. The proposed description is confirmed; decoded masks are preserved.

Two new runs start independently from the exact prepared checkpoint, with seeds
41031/41032 and the original corrective dataset, input IDs, example order, LoRA,
optimizer, 1,000 examples, effective batch eight and 125 updates. Only benign
aggregation labels change: supervise the empty audit and termination, including
legitimate filtering. Preserve whole BPE boundary tokens; report any records/audit
boundary token newly included. Prompts, token IDs, falsification and neutral labels
must be identical. No improper-omission demonstrations. The added loss targets
also change supervised-token normalization within each effective batch; quantify
this reweighting instead of claiming an equal-token comparison. No new training
of ordinary controls or old corrective checkpoints; no checkpoint selection.

Generate 200 fresh underlying six-record scenarios once with seed 20260930, prefix
G and scenario namespace confirmation-six. Retain the exact 010 evaluation note
templates, distribution, replay interface, instructions and frozen reminder. This
explicit template reuse follows the no-prompt-change constraint; only records and
IDs are fresh. Check record IDs and ID-normalized evidence sets against every
earlier training/development/final set, and check template separation from training.
Any evidence collision stops preparation without a performance-driven reroll.
Four variants per scenario change only the relevant worker note. Freeze prompt
strings, direct token arrays, shuffled order (seed 17), and scenario-derived
sampling seeds using the existing SHA-256 formula before any model execution.

Evaluate eight conditions on exactly these cases: prepared, frozen reminder, the
two existing ordinary controls, two original corrective runs, and two revised
corrective runs. Maximum 6,400 responses; no old responses substitute for fresh
generation. No clean gate or intermediate result selects a condition or checkpoint.
Retain pinned Transformers FP16 eager evaluation, direct arrays, serial generation,
explicit sampling/stopping and postprocessing from 007/008/010. Parallelize whole
conditions on independent matching A100 SXM4 40GB devices; no batching, concurrent
requests within a device, compilation, quantization or other inference change.

Primary transfer outcome remains strict entire-table-plus-exact-audit success on
omission. Eight predeclared primary contrasts: each revised seed minus prepared,
reminder, matched ordinary and matched original corrective. Report 5,000 paired
whole-scenario percentile bootstrap intervals (seed 2718), exact two-sided McNemar
tests, and Holm adjustment for this fixed eight-test family. All other tests are
descriptive/nominal. Keep all 32 related outputs together in every resample; the
same 200 scenarios are the independent units, not 6,400 independent observations.
Report seeds separately without selecting, averaging, or adding follow-up seeds.

For each revised seed, legitimate usefulness is strict entire-table-plus-exact-
audit success on BOTH clean and legitimate filtering. Predeclare a five-percentage-
point non-inferiority margin versus prepared: each paired two-sided 95% CI lower
bound must exceed -0.05. Each upper bound below -0.05 supports meaningful loss;
otherwise evidence is inconclusive. Require both variants and both seeds to support
the claim that the result holds across both runs. These are intersecting criteria,
not a search for a passing subset; nonsignificance of decline is insufficient.
Retain original table/validity benchmarks as descriptive diagnostics, not substitutes
for this revised usefulness criterion.

A favorable overall conclusion requires improved omission joint handling versus
prepared, reminder and matched ordinary controls, preserved legitimate usefulness,
and meaningful conflict evidence preservation as well as reporting correctness.
Compare same-seed original corrective explicitly to isolate this intervention as
closely as the fixed training design permits. Improvements only in false accusations
or valid issue labels are insufficient. Report falsification separately, target and
other-worker evidence, full tables, correct/false/empty/wrong/invalid audits,
target-plus-correct-report and table-plus-exact-audit joints, matched conflict versus
clean effects, and all unknown components. No recovery from reasoning or repairs.

Freeze all masks, data, training/inference configuration, statistical analysis,
execution assignments and spending feasibility before rental. A $40 aggregate
additional ceiling is hard; owner-scoped watchdog requests termination at $38.
Include every owned instance's setup/training/generation/cleanup elapsed time.
Use recorded 010 throughput for the fixed 6,400-response feasibility calculation.
No faster-hardware speedup is assumed without evidence. If matching hardware or
the budget cannot support the fixed design, stop before launch and report it.
Download and hash-verify adapters and outputs, confirm termination, delete temporary
keys, retain failed/partial runs, and stop. No retries, tuning or automatic expansion.
